# 飞书多维表格任务协议

## 初始化分支

每次新会话先问用户是否已有本工作流的飞书 Base：

- 已有 Base：索取链接，解析真实`base_token`、`table_id`和`view_id`，再按本协议检查差异。
- 没有 Base：询问 Base 名称和表名，使用`+base-create`创建完整初始表；不要只创建空表后让用户手工补字段。

新建 Base 时，初始表必须一次覆盖本协议的必需字段、完整状态选项和1–2段字段。随后按用户选择创建基础版或扩展版提交表单，以及四个工作视图。所有创建操作完成后回读并验证。

## 必需字段

- 产品名
- 任务ID
- 创建日期或提交日期
- 产品图（附件）
- 爆款视频（附件）
- 任务状态
- 验收结果
- 验收意见
- 爆款拆解
- 新脚本
- 分段数量
- 当前片段
- 最后成功步骤
- 下次运行时间
- 当前生成入口
- Gemini额度状态
- Flow额度状态
- 额度检查时间
- 运行日志
- 分镜图提示词 1–2
- 分镜图 1–2（附件）
- 视频提示词 1–2
- 成品视频 1–2（附件）
- 尾帧 1（附件）
- 失败原因
- 重试次数

每次运行先用 `+field-list` 读取真实字段名和ID。字段缺失时先报告并取得结构修改授权，不要猜字段ID或默默降级：

- 断点续跑：`当前片段`、`最后成功步骤`、`下次运行时间`。
- 额度管理：`当前生成入口`、`Gemini额度状态`、`Flow额度状态`、`额度检查时间`、`运行日志`。
- 人工审核：`验收结果`、`验收意见`。
- 连续性资产：`尾帧 1`。

## 状态机

```text
空 / 待处理
  -> 拆解中
  -> 分镜图生成中
  -> 视频生成中
  -> 待验收
  -> 已完成
人工废弃 -> 已废弃

任一步失败 -> 失败
需要用户完成保存或其他操作 -> 待用户操作 -> 返回原阶段
额度受限 -> 等待额度恢复 -> 到时返回视频生成中
```

`已完成`是用户验收状态，不是机器生成结束状态。所有片段机器验收通过后只能进入`待验收`；用户明确确认后才能进入`已完成`。

## 人工审核与返工

- `验收结果`使用单选：`通过`、`返工`、`废弃`，并在工作视图中排在`验收意见`前。
- 每次运行先查`验收结果=返工`，再认领新任务。
- `通过`：把`任务状态`更新为`已完成`并回读。
- `废弃`：把`任务状态`更新为`已废弃`并回读，后续不再处理。
- `返工`：读取`验收意见`确定重做片段。返工第1段且存在第2段时，必须随新第1段重新生成尾帧1和第2段。
- 新成品上传并回读成功后，清空`验收结果`并把状态改回`待验收`；生成失败时保留`返工`，防止任务丢失。
- 清空前把原验收意见、返工片段和结果追加到`运行日志`；`验收意见`保留供追溯，不作为重复生成触发条件。

## 额度与运行日志

- `当前生成入口`使用单选：`Gemini`、`Flow`、`等待`。
- `Gemini额度状态`和`Flow额度状态`保存当次页面原文或可验证摘要，不写未经验证的固定额度。
- `额度检查时间`只写实际读取页面或提交结果的时间。
- `运行日志`按时间追加：`时间+时区 | 账号别名 | Chrome配置名 | 记录ID | 片段 | 入口 | 动作 | 结果 | 额度快照 | 恢复提示原文 | 下次检查时间 | 下一步`。写入前先回读旧值，避免重试时覆盖历史。
- 连续成功提交3个Gemini视频后可写`疑似耗尽（3次经验阈值）`并切换Flow，但只有页面或生成返回明确拒绝时才能写`已耗尽`。
- Flow用完或不足后，先重新检查Gemini并把检查结果追加到`运行日志`；只有重新检查后Gemini仍受限，才把`当前生成入口`写为`等待`。

### 多账号可选表

只有用户确认启用多账号时，在同一 Base 新建独立的`账号额度`表；不要向任务主表增加一组重复账号字段。该表保存账号别名、Chrome配置名、允许入口、启用状态、优先级、Gemini状态与连续成功数、Gemini恢复提示原文、Flow状态与积分、Flow单次成本、额度检查时间、下次检查时间、最后使用时间、当前任务锁和账号运行日志。完整字段与选取算法见 [account-routing.md](account-routing.md)。

单账号不创建该表，只在任务的`运行日志`和`最后成功步骤`记录实际账号别名。任何表都不得保存密码、Cookie、Token、完整邮箱或Chrome配置绝对路径。

## 表单规则

- 创建前先询问用户使用基础版还是扩展版；当前用户未选择扩展时不要自行增加题目。
- 基础版只要求`产品图`和`爆款视频`，两者都设为必填；`产品名`可以作为可选题，题目应明确叫`产品名或备注（可选）`，不要只显示成`备注`却写入主字段`产品名`。
- 扩展版仅按用户选择增加目标国家/语言、产品核心卖点、禁止出现的内容、旁白/音乐偏好等可选题，不默认全部创建。
- 提交日期使用 Base 的系统创建时间，不要求用户手填。
- 脚本、提示词、分镜、成品、状态和失败记录等内部字段不出现在用户表单。

## 推荐视图

- `待处理队列`：状态为空或`待处理`。
- `处理中`：`拆解中`、`分镜图生成中`、`视频生成中`、`等待额度恢复`或`待用户操作`。
- `待验收`：只显示等待用户确认的任务及分镜、成品字段。
- `已完成`：只显示用户已确认任务。

主工作视图不要默认展示全部内部字段；按阶段显示必要字段，降低人工误改风险。

## 认领条件

```text
(任务状态为空 OR 任务状态=待处理)
AND 产品图非空
AND 爆款视频非空
```

把状态改成`拆解中`后再下载素材。状态更新成功才算认领成功；失败时不要继续处理该记录。

认领时若`任务ID`为空，生成唯一任务ID并写回。同步写`当前片段=1`、`最后成功步骤=已认领`。每个附件上传并回读成功后更新`最后成功步骤`，确保跨会话可以从 Base 恢复。

## 附件规则

- Base附件只使用 `lark-cli base +record-download-attachment` 和 `+record-upload-attachment`。
- 下载和上传使用相对当前工作目录的安全路径。
- 每生成一张分镜图立即上传对应字段并回读确认。
- 每下载一段成品视频立即上传对应字段并回读确认。
- 不把附件token作为普通CellValue写入。

### 成品视频回传闭环

1. 上传前用`+record-get`读取目标`成品视频 i`字段。若已存在同名、同大小或已经验收过的附件，先复用或向用户确认替换，不得因重试重复追加。
2. 从成品文件所在目录执行上传命令，并向命令传相对路径；绝对路径可能触发`unsafe file path`。
3. 上传命令返回成功后，立即再次用`+record-get`回读，核对附件的`file_token`、`name`和`size`。只有三项存在且与本地成品相符，才算回传成功。
4. 多段任务逐段执行“上传→回读”，不要等所有片段结束后批量回传。
5. 只有所有计划中的`成品视频 i`都回读成功，才把`任务状态`更新为`待验收`。
6. 用户明确确认整条任务后，再把状态更新为`已完成`并最终`+record-get`；不能只凭上传或状态更新命令的成功返回报告完成。

## 分段规则

- `分段数量`只能写1或2。
- 只填写实际需要的段字段；未使用的后续段字段保持空值。
- 第2段的视频提示词必须明确写入“使用第1段真实尾帧续接”。
- 第1段完成后，把消除水印版的真实稳定尾帧上传到`尾帧 1`；第2段不需要为续接预留尾帧。

## 失败和重试

- 保存可执行的失败原因，例如“Gemini页面仅显示明天再来”“Flow积分不足”“生成结果不是9:16”。
- 每次真实重试前增加`重试次数`。
- 浏览器限额不等于永久失败；若已安排恢复时间续跑，改为`等待额度恢复`并记录`下次运行时间`。
- 只有不可恢复错误或达到用户指定重试上限时改为`失败`。
