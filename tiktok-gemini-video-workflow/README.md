# TikTok Gemini 视频工作流

把飞书多维表格里的产品图和爆款视频，处理为可追踪、可返工的 TikTok 带货视频任务。

## 能做什么

1. 检查或创建飞书多维表格、提交表单和工作视图。
2. 优先读取人工标记的返工任务，再认领新任务。
3. 拆解爆款，生成新脚本、详细的全英文9:16九宫格分镜提示词和逐帧视频提示词。
4. 记录用户指定的Google账号别名和Chrome配置；多账号时先轮询所有Gemini额度，再轮询Flow积分。
5. 检查原作文字钩子；Gemini/Flow缺字或乱码时，后期按原文补字。
6. 下载成片、消除 Gemini 可见星形水印、验证文字、画幅和音轨。
7. 把分镜、尾帧、成品、额度和运行日志回填飞书。
8. 成品进入待验收，由人工选择通过、返工或废弃。

## 分段规则

- 15 秒及以下：1 段。
- 15–30 秒：2 段。
- 超过 30 秒：询问用户是否压缩成两段或更换参考视频。
- 第 2 段必须使用第 1 段真实成品尾帧续接。

## 提示词规范

- 分镜图提示词和视频提示词统一使用英文；必须原样保真的产品名、实体标签/Logo、原作屏幕文字和对白除外。
- 每段使用一张完整的9:16、3×3九宫格；不改成六宫格，也不拆成九张独立参考图。
- 九宫格每格都写明时间、景别、叙事作用、可见动作与状态、运镜和情绪。
- 分镜图和视频提示词独立计数：分镜图固定是一张9:16九宫格，只表达9个关键状态；视频提示词重新拆解原片，把每一个画面状态分别写成`VIDEO FRAME 01...N`。
- 视频提示词不受九宫格9格限制。原片拆出16个画面状态就写16条，不能压成6条、7条或9条。
- 每个视频帧条目单独写时间码、参考图、起始连续状态、左右肢体、商品/零件状态、持握部位、工作端、接触对象、运动方向、镜头、音频、转场和结束连续状态。
- 所有视频帧条目时长总和必须等于生成器实时片长，时间码连续且不遗漏原片状态；两段任务把全部状态分配到两段，第2段继续使用真实尾帧。
- 主模特身份只由指定参考图锁定，不用文字重新猜测面部特征；副角色身份不得重复。多张产品图共同约束同一个商品，不按图片数量复制商品或零件。
- 每条任务必须在“完全无可见文字”和“仅保留产品实体标签”两种策略中选择一个；原作屏幕文字仍进入后期清单，不依赖视频模型生成。
- 第二段以第一段真实成品尾帧为最高优先级精确起点，再用上一段分镜锁定人物与场景、产品图锁定产品身份。
- 原作屏幕文字进入后期清单，不依赖视频模型正确生成字幕。

## 最小输入

- 产品图。
- 想复刻结构的爆款视频。
- 可选的产品名或备注。

首次运行还会确认工作目录、成品目录、Chrome 配置和 Google 账号、Base、交付方式、通知方式及是否设置定时任务。

账号规则：

- 单账号记录账号别名、Chrome配置名和允许入口。
- 多账号记录启用状态、优先级、账号粘性和是否允许自动切换。
- 账号状态使用独立`账号额度`表，任务主表不堆叠重复账号字段。
- 日志记录实际使用账号、入口、额度快照、恢复提示原文、切换原因和下一步。
- Skill不保存密码、Cookie、Token、完整邮箱或本机Chrome配置路径。

新建表单时可选择：

- 基础版：只收集产品图、爆款视频和可选产品名。
- 扩展版：按需增加目标国家/语言、产品卖点、禁止内容、旁白/音乐偏好。

## 人工审核

- 通过：任务进入已完成。
- 返工：Codex 下次运行时优先读取验收意见并重新生成；新成品上传成功后清空“验收结果”，重新进入待验收。
- 废弃：任务进入已废弃，不再处理。

废片由人工验收判断，Skill 不会自行判断或擅自裁剪。

## 安装

1. 解压压缩包。
2. 把 `tiktok-gemini-video-workflow` 文件夹放入 Codex Skills 目录。
3. 重启 Codex。
4. 使用类似“处理飞书里的爆款视频复刻任务”启动。

Skill 会在执行前检查飞书 CLI、Chrome 控制能力、`ffmpeg`、`ffprobe`和去水印能力；缺失的依赖必须先说明用途并获得用户同意后再安装。
